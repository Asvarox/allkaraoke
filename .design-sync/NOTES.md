# design-sync notes

- **Scope**: only the AKUI component library (`src/modules/elements/akui/`) is synced — bottom-sheet, button, chip, icon, kbd, menu, selector, skeleton. The repo also has storybook stories for app-level screens/features (history-page, player, post-game, song-preview, autocomplete, keyboard, mic-check-slot, game-overlay) — those are intentionally excluded, they aren't reusable design-system primitives.
- **No package build**: this repo doesn't publish AKUI as a separate npm package (no `dist/`, no `module`/`exports` in package.json — it's app-internal source). `cfg.entry` points at `.design-sync/entry.tsx`, a hand-written barrel re-exporting the AKUI components directly from `~/modules/elements/akui/*` (esbuild bundles the TSX source directly, no build step needed). `cfg.tsconfig` is set so the `~/*` → `./src/*` alias resolves.
- **CSS**: Tailwind v4, CSS-first config (`@import 'tailwindcss'` in `src/index.css`, no separate compiled stylesheet checked into the repo). Relying on `[CSS_FROM_STORYBOOK]` scraping from the compiled `sb-reference` build rather than `cfg.cssEntry`.
- **Fonts**: no `@font-face` rules in the repo's CSS — `body`/`button`/`input` font-family list is all system fonts (Seravek, Gill Sans Nova, Ubuntu, Calibri, DejaVu Sans, source-sans-pro). No custom brand font to ship. (The `nunito-sans-*.woff2` files in the storybook build output are Storybook's own manager UI assets, not used by any AKUI component or repo CSS — not shipped in the DS bundle.)
- **No provider**: `.storybook/preview.tsx` decorator is a no-op `<>{Story}</>` wrapper — no context/theme provider needed for previews.
- **`.design-sync/dts-out/` is generated, not authored**: component discovery (`exportedNames()`) needs a real `.d.ts` for the barrel, which esbuild alone doesn't produce. `.design-sync/package.json` (`name: "akui"`, `types: "./dts-out/entry.d.ts"`) plus `.design-sync/tsconfig.dts.json` (extends the repo tsconfig, `declaration`+`emitDeclarationOnly`, `types: ["node"]` for the `is-e2-e.ts` global lookup, `allowImportingTsExtensions` for the `menu.tsx` disambiguation import) drive `node .design-sync/gen-dts.mjs`, which runs `tsc`, flattens the emitted tree from `dts-out/.design-sync/entry.d.ts` → `dts-out/entry.d.ts`, and rewrites `~/...` alias specifiers to `./src/...` relative paths (design-sync's own ts-morph scan has no `paths` config, so alias specifiers in the `.d.ts` wouldn't resolve). **Run `node .design-sync/gen-dts.mjs` before every build/re-sync** — it's the de facto `buildCmd` for this repo, just not expressible as a single shell one-liner in `cfg.buildCmd`.
- **[GENERAL] fixed a real cross-browser bug**: `src/modules/utils/is-e2-e.ts` (imported by `Button` and `Menu`) read the Node-only `global` at module scope. The app itself papers over this with `<script>var global = window;</script>` in `index.html` / `.storybook/preview-head.html`, but design-sync's standalone `_ds_bundle.js` has no such polyfill and `bundle.mjs`/`emit.mjs` can't be forked to inject one — the ReferenceError crashed the whole IIFE before `window.AKUI` was assigned, so ALL 8 components failed `[BUNDLE_EXPORT]` at once even though only 2 use it. Fixed at the source: `global` → `globalThis` (standard ES2020+, identical behavior in Node and browsers). User confirmed and approved this source change.
- **Accepted `[FONT_MISSING]`** (Seravek, Gill Sans Nova, Calibri, source-sans-pro, source-code-pro): these are system-font fallback stacks in `src/index.css`, not a shipped brand font — no `@font-face` anywhere in the repo. User explicitly OK'd system-font substitutes for the DS pane.
- **Accepted `[TOKENS_MISSING]`** (50 `--motion-*` custom properties from the `tailwindcss-motion` plugin): these are set at runtime by the plugin's JS, not shipped in a static stylesheet — expected absence, not a real gap.
- **`cfg.overrides`**: `Button`, `Menu`, `Skeleton` all use `cardMode: "column"` (their stories render wider than a grid cell — `[GRID_OVERFLOW]`).

## Re-sync risks

- The barrel entry (`.design-sync/entry.tsx`) is hand-maintained — if a new AKUI component is added or an existing one's export name changes, this file needs a matching edit or the new component won't be discovered.
- No real "build" exists for this package, so `buildCmd` is intentionally unset in config — a re-sync needs, in order: `pnpm install` (if the lockfile changed), `node .design-sync/gen-dts.mjs` (always — see the dts-out note above), and a fresh `.design-sync/sb-reference` rebuild (`npx storybook build -c .storybook -o .design-sync/sb-reference`, run from repo root) if AKUI source or stories changed.
- If `src/modules/utils/is-e2-e.ts` (or any other module AKUI components import transitively) reintroduces a Node-only global (`global`, `process`, etc.) at module scope, every AKUI component will fail `[BUNDLE_EXPORT]` at once — this is a whole-bundle canary, not a per-component issue. Chase it the same way: find the module-scope global read, switch to `globalThis`.
